# ThermalTrace

ThermalTrace 是一个 Windows 上的笔记本散热长期趋势记录工具。它不显示实时温度，而是在后台持续记录真实使用时的负载与温度，用来回答一个具体问题：

**在同样的负载下，这台机器现在比一个月前热了多少？**

清灰、换硅脂前后各记录一段时间，就能用同一口径的数据比较前后变化。程序不依赖特定机型，但目前主要在 Intel 平台验证过。

## 两个版本

安装包分两种，采样、趋势和解读功能相同，数据格式也相同，区别只在墨水屏推送：

- **普通版**：不含墨水屏推送，对外发布的是这一版。
- **极趣推送版（Zectrix）**：带极趣 Note4 墨水屏推送。只有在有极趣 Note4 时才有用；目前不对外分发。

| 功能 | 普通版 | 极趣推送版（Zectrix） |
|---|---|---|
| 后台采样、今日概览、趋势分析、解读 | 支持 | 支持 |
| 解读页生成 HTML 报告 | 支持 | 支持 |
| 极趣 Note4 墨水屏推送 | 不支持 | 支持（需要有极趣 Note4） |
| 设置页「墨水屏推送」分区、`--push` 命令 | 无 | 有 |
| `--eink` 在本机生成 PNG 预览 | 支持 | 支持 |

普通版在构建时裁掉了推送服务、设置页推送分区、后台推送调度和 `--push` 命令，界面里没有任何推送入口，也不会生成推送状态或推送日志。`--eink` 仍可在本机生成图片，只是不会上传。

极趣推送版的推送会把最多两张 400×300 黑白 PNG 经极趣云发到设备（每个图片槽一张，第二个槽不适用时只推一张），这是它唯一会外发图片的功能。普通版不包含这段代码，不会发起任何推送请求。

## 它解决什么问题

单看一次温度无法判断清灰是否有效，因为至少四类因素会干扰：

- **传感器口径不同**：不同工具读同一时刻的 MSR，结果可能差 3~8℃。
- **负载不同**：50% 占用和 100% 占用的温度没有可比性。
- **室温不同**：夏天 30℃ 和冬天 15℃ 的静置温度能差十几度。
- **噪声大于变化**：传感器粒度通常是 1℃，单点读数没有意义。

ThermalTrace 对应的做法是：

- 只比较**同一台机器、同一套传感器绑定**的纵向变化，不与其他机器的数字横向比较。
- 每个时间片按**单核峰值利用率**分档，只在同一档内比较。默认合并为空闲、轻度、中等、重度、满载五类，边界可以在设置页调整。
- 主指标是 **ΔT（温升）= 该档加权平均温度 − 当天空闲档最低温**，不是绝对温度。
- 默认每 **30 分钟**一个时间片，聚合均值、P95 和最大值，并按样本数加权。时间片长度可在 `settings.json` 的 `sampler.sliceMinutes` 中调整为 5–120 分钟。

## 它不做什么

- 不做实时温度显示、实时曲线或告警气泡。需要实时监控请继续使用 LiteMonitor 等工具。
- 不跑合成负载基准测试，只记录真实使用。
- 不保存逐秒原始数据，只保存聚合后的时间片。
- 不把趋势解读交给外部 AI。解读在程序内完成；「复制数据摘要」只是把文字放进剪贴板，由你自己决定贴到哪里。
- 不提供云端账号或同步服务。采集数据留在本机。

## 系统要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 1607 及以上，或 Windows 11 |
| 架构 | 64 位（x64）。**不支持 ARM64** |
| 磁盘 | 安装后约 80 MB |
| 运行权限 | 手动启动时需要管理员权限，每次双击都会弹 UAC；由开机自启拉起时不弹 |
| 运行库 | 不需要安装 .NET、运行库或额外驱动 |
| 平台验证 | 主要在 Intel 平台验证；AMD 平台可用性未验证 |

读取 CPU 温度需要访问 MSR 寄存器，程序通过 WinRing0 内核驱动完成，因此运行时必须提权。安装包本身不要求管理员权限。

## 安装

1. 从项目的 Release 页面下载最新的普通版安装包，文件名形如 `ThermalTrace-<版本>-Setup.exe`。
2. 双击安装包，按向导点「下一步」。默认安装到：

   ```
   %LOCALAPPDATA%\Programs\ThermalTrace-Standard
   ```

   安装过程不弹 UAC。
3. 安装完成后启动程序。**第一次启动会弹一次 UAC，请点「是」**，否则读不到任何温度。
4. 启动后屏幕上不会出现窗口，这是正常现象。程序在后台运行，只在右下角托盘放一个图标。
5. 首次启动时托盘会询问是否开启开机自启。选「是」会注册一个计划任务；之后随时可以在「设置 → 开机自启」里关闭。

已装过旧版时，直接双击新安装包覆盖即可，不需要先卸载，历史数据会保留。

更完整的安装、UAC 与排错说明见本文「常见问题」一节。

## 日常使用

装好后程序在后台常驻，右下角有一个托盘图标。Win11 默认可能把它收在任务栏的「^」折叠区里。

- **鼠标悬停**：查看当前温度、单核峰值和今日已落盘的时间片数。
- **双击图标**或右键「打开主窗口」：打开主窗口。
- 右键菜单还提供「重新自检…」「采样状态 / 重启」和「退出」。

主窗口有四个页签。

### 今日概览

显示今天已经落盘的数据：

- 页头：日期、环境气温、已记录时长、样本数，以及当前口径说明。
- **交流 / 电池**切换。两路数据分开统计，不混算。
- 五张负载档卡片：空闲、轻度、中等、重度、满载。每张显示加权均温、ΔT、时长、样本数、平均功耗和超过 85℃ 的占比。
- 页脚：今日最高温度、超过 85℃ 的累计分钟数，以及 GPU、SSD 的当前值。

没有采到的档显示「—」，不显示 0℃。0 会被读成「凉快」，「—」才表示「没采到」。

### 趋势分析

按天查看历史变化，有三个视图：

- **折线**：各负载档的 ΔT 走势，同时叠加当天空闲基线和环境气温。
- **柱状**：当前范围与上一个同期范围对比，直接看变化幅度。
- **硬件**：GPU 的当日均温与使用时长，SSD 的累计写入与剩余寿命。

范围可选近 7 天、近 30 天或全部。柱状视图没有上期可比数据时，「全部」不可用。数据不足 3 天时，页面会直接说明还需要几天，不画空图。折线和柱状视图底部还会显示本期各档的累计时长、占比和样本数。

### 解读

按范围生成一份文字解读，包括健康度色签、一句话总结、证据、可能原因与验证方法、建议，以及清灰基准信息。

- 范围可选近 7 天、近 30 天或自上次清灰。未填写清灰基准日时，「自上次清灰」不可用。
- 近 7 天 / 近 30 天范围下，数据不足 14 天时只说明还差几天，不给趋势判定；自上次清灰范围下，不足 7 天仍给结论，但会标注样本偏少、结论偏弱。
- 底部「复制数据摘要」把当前窗口的数字和口径定义复制到剪贴板，方便你自己贴到别处。这一步不联网。
- 右上角「生成并打开 HTML 报告」在普通版和极趣推送版里都有。报告在后台生成，保存到 `reports\trend-yyyyMMdd-HHmm.html`，然后用默认浏览器打开。报告结论固定按近 30 天窗口计算，与趋势页当前选择的窗口可能不同。

### 设置

- 开机自启开关，显示真实状态。
- 位置与环境气温：可联网获取，也可手动填写经纬度。
- 外观主题：跟随系统、浅色、深色。
- 负载类别边界与名称。边界只影响展示层的合并方式，不需要重新采集数据。
- 清灰基准日。
- 维护：重新自检、重新绑定传感器。

普通版没有「墨水屏推送」分区。

## 数据存放位置

数据默认保存在：

```
%LOCALAPPDATA%\ThermalTrace\
├── settings.json                 # 全部设置
├── slice-snapshot.json           # 当前时间片的工作快照，写盘后删除
├── caliber.json                  # 传感器口径历史
├── daily\YYYY-MM-DD.csv          # 逐日数据，Excel 可直接打开
├── health\ssd.csv                # SSD 寿命计数器，一天一行
├── weather\ambient-YYYY-MM.csv   # 环境气温缓存
├── reports\trend-*.html          # 生成的 HTML 报告
├── eink\                         # --eink 生成的本地预览图
└── logs\
    ├── boot.txt                  # 每次启动的记录
    └── sampler.txt               # 采样与运行日志
```

程序本体在 `%LOCALAPPDATA%\Programs\ThermalTrace-Standard\ThermalTrace.exe`，与数据目录分开。

- 数据量约为每天 35 KB，一年十几 MB。
- 时间片默认 30 分钟，可配 5–120 分钟。程序每 5 分钟保存一次当前片快照，断电或强制结束最多丢约 5 分钟。
- `daily\*.csv` 的列只增不改。旧文件列数较少时，缺的列按「缺失」处理，不填 0，也不丢行。
- 普通版不会生成 `push-state.json`、`logs\push.txt` 或 `eink\last-push*.png`。

## 隐私

- 温度、功耗、利用率等采集数据只保存在本机，程序没有账号系统，也不会上传测量数据。
- 默认会联网获取环境气温：先把**公网 IP** 发给 `ip-api.com`（明文 HTTP）做城市级粗略定位，再向 Open-Meteo 请求该城市的气温。不需要时可在「设置 → 位置与环境气温」关闭，或手动填写经纬度，之后可完全离线运行。断网时会降级为本地代理值，不影响温度记录。
- 普通版不含墨水屏推送，不会上传图片、位置名或设备信息。
- 极趣推送版的墨水屏推送一次最多发送两张 400×300 的 1 位黑白 PNG（每个图片槽一张），不发送 CSV 原始数据、经纬度、机器标识或传感器明细。只有在有极趣 Note4 时才会用到这项功能。

## 卸载

1. 先从托盘菜单点「退出」。
2. 打开「控制面板 → 程序和功能」，找到「ThermalTrace 普通版」，点「卸载」。
3. 卸载过程不弹 UAC。最后会单独询问是否删除历史数据，**默认保留**。

保留数据时，重新安装后可以继续使用原来的记录。选择删除后，`%LOCALAPPDATA%\ThermalTrace\` 下的温度记录、设置和报告会一起删除。

## 常见问题

**双击后没有窗口，是不是闪退了？**

不是。程序是后台常驻程序，启动后本来就不开窗口。看右下角托盘，Win11 可能在「^」折叠区里。双击托盘图标即可打开主窗口。

**所有温度都显示「—」？**

最常见的原因是安全软件拦截了 WinRing0 内核驱动。把 `ThermalTrace.exe` 和安装目录加入白名单，然后**重启电脑**，再打开「设置」页点「重新自检」。驱动是在加载阶段被拦截的，不重启不会生效。

**刚装上今天没有数据？**

正常。数据默认每 30 分钟才落盘一个时间片，刚装好需要等一会儿。也可以在「今日概览」的空态里点「立即自检」，确认传感器是否可读。

**设置里显示已开启开机自启，但任务管理器里看不到？**

开机自启使用的是计划任务，不是注册表启动项或启动文件夹。可以在「任务计划程序」里找到名为 `ThermalTrace` 的任务；设置页显示的是实际状态，不是「调用没报错」。

**Windows 提示「未知发布者」或 SmartScreen 拦截？**

程序未做代码签名，可能出现这个提示。点「更多信息」→「仍要运行」即可。

**和其他硬件监控软件同时运行，读数会互相影响吗？**

可能。多个工具同时访问 MSR 可能争抢独占访问，导致读数间歇为空。需要对比数据时，建议先关闭其他监控工具。

## 从源码构建

构建需要 Windows x64、.NET 8 SDK；打包安装程序还需要 Inno Setup 6。目标机器不需要安装 .NET，发布产物是自包含单文件 exe。

```powershell
# 一次性准备 .NET 8 SDK（安装到项目 .tools\，不污染系统）
powershell -ExecutionPolicy Bypass -File scripts\install-dotnet.ps1

# 编译
powershell -ExecutionPolicy Bypass -File scripts\build.ps1

# 发布单文件 exe
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1                   # 极趣推送版（含推送）
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1 -Edition standard # 普通版（不含推送）

# 打普通版安装包
powershell -ExecutionPolicy Bypass -File scripts\build-beta.ps1
```

更完整的构建、发布与部署说明见 [BUILD.md](BUILD.md)。
